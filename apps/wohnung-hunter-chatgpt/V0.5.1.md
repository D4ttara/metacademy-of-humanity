# Wohnung Hunter v0.5.1

v0.5.1 is an additive safety patch on top of the existing `WohnungHunter.gs` v0.5.

## Install

1. Keep the existing v0.5 `WohnungHunter.gs` in the bound Apps Script project.
2. Add a second script file and paste the complete contents of `apps-script/WohnungHunter.v051.gs`.
3. Save and run `setupWohnungHunter051()` once.
4. After setup, the automatic five-minute trigger is `scanRentalMail051`; the old `scanRentalMail` trigger is removed.
5. Do not run the old `setupWohnungHunter()` again unless intentionally rolling back the patch.

No web deployment is required.

## What v0.5.1 changes

- Filters observed search-alert noise such as `Benachrichtigung zu Ihrer Immobiliensuche` from ohne-makler.
- Keeps the v0.5 rule that Gmail thread IDs are never object identities.
- Merges an ID-less portal follow-up only when portal, exact normalized title, and sender domain identify one unique stable canonical ID.
- Consolidates Dawonia/Immomio events only with the strong signature exact address + rooms + sqm.
- Reads explicit terminal history from the current manual rows and `WH_Backup_v04`.
- Expands a confirmed withdrawal object number through historical aliases. This protects the Putzbrunn 10765 case across its viewing mail and Immowelt representation.
- Reapplies `withdrawn`, `rejected`, or `closed` after every automatic scan so older application/viewing/documents mail cannot reopen a terminal object.
- Never writes the user-managed columns F (`ÖPNV / Lage`), J (`Dokumente`), L (`Notizen`), or M (`Score`).

The base parser version in column T remains `0.5` on purpose. The patch version is stored separately in Script Properties as `WH_PATCH_VERSION=0.5.1`; changing T would make the v0.5 renderer treat its own rows as manual rows.

## Manual functions

- `runWohnungHunter051Manual()` runs only the safety normalizer.
- `repairRecentBatch051Manual()` runs one repair block and then the safety normalizer.
- `showWohnungHunter051Status()` shows the patch trigger and base-parser version.
