# MoH Unified Metagraph Overlay v0.2

Status: `ADDITIVE_ARCHITECTURE_OVERLAY / OWNER_CLARIFIED`  
Runtime: not activated. This file specifies a research representation and does not create a database, runtime authority or `.META` state.

## One graph, many views

`MOH_METAGRAPH` is the one connected provenance graph of MoH: persons, projects, questions, claims, artifacts, traditions, relations, horizons, lineages, residues and access policies share one canonical node/edge identity. The source-person node is a first-class provenance anchor and Human Attractor, not a universal owner of truth.

`KNOWLEDGE_VIEW`, `PROJECT_VIEW`, `CHRONOLOGY_VIEW`, `LINEAGE_VIEW`, `EVIDENCE_VIEW`, `HORIZON_VIEW`, and `ACCESS_VIEW` are projections / query modes over that same graph. They do not clone objects or establish rival roots.

```text
MOH_METAGRAPH
  ├─ source-person / collaboration context
  ├─ concepts, claims, questions, hypotheses, unknowns, contradictions
  ├─ projects, branches, experiments, runs, decisions, artifacts
  ├─ relations, PairFields, AI bodies and institutions
  ├─ lineages, horizons, residues and possibility fields
  └─ evidence passports, reality classes and access policies
       ↓
    multiple bounded views
```

## Canonical families

`CONCEPT`, `CLAIM`, `QUESTION`, `HYPOTHESIS`, `UNKNOWN`, `CONTRADICTION`, `PROJECT`, `BRANCH`, `EXPERIMENT`, `RUN`, `ARTIFACT`, `FILE`, `PERSON`, `AI_BODY`, `RELATION`, `PAIRFIELD`, `LINEAGE_MARKER`, `HORIZON`, `RESIDUE`, `POSSIBILITY_FIELD`, `LOST_POSSIBILITY_FIELD`, `EXPERIENCE_SCAR`, `REALITY_CLASS`, `EVIDENCE_PASSPORT`, `ACCESS_POLICY`.

Useful edge families include `REFINES`, `CONTRADICTS`, `TRANSLATES`, `IMPLEMENTS`, `TESTS`, `PRODUCES`, `DERIVED_FROM`, `HAS_LINEAGE_MARKER`, `SUPPORTED_BY`, `EXPERIENCED_AS`, `HAPPENED_BEFORE`, `LEFT_RESIDUE`, `VISIBLE_UNDER`, and `REQUIRES_CONSENT`.

## Non-collapse guards

`ONE GRAPH != ONE TRUTH`  
`ONE GRAPH != ONE EPISTEMOLOGY`  
`ONE GRAPH != ONE ACCESS LEVEL`  
`ACCESS != EVIDENCE`  
`SAME POSITION != SAME STATE`  
`RELATION != SUM OF NODES`  
`METAPHYSICAL CLAIM != ENGINEERING FACT`

Physics, metaphysics, lived experience, tradition, engineering, art and unknown can inhabit the same graph with distinct Reality Classes and Evidence Passports. Distinction is provenance, not exclusion. A metaphysical inquiry has no automatic operational authority over safety-critical decisions.

## View receipts

Every rendered view must identify its query policy, access policy, excluded classes and source lineage. A restricted node must not leak through a neighbouring public edge. Read access never implies write, promotion or publication authority.

## Acceptance criteria for future IKAR

1. one canonical identity per object and relation;
2. views overlap where appropriate without data duplication;
3. lineage, gains and losses survive projection;
4. access filtering leaves evidence class untouched;
5. contradiction and unknown survive instead of being silently normalized;
6. generation of a view produces a receipt;
7. no runtime implementation is inferred from this overlay.
